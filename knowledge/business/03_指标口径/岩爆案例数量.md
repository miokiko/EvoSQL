# 全部案例数

<!-- planning -->
案例数、案例总数、全部案例数量默认指案例主档中不同的非空案例编码数量。不添加隐含有效状态或时间过滤，明细重复不增加案例数。
<!-- /planning -->

- 默认定义：对非空 `t_caseinfo.c_caseCode` 去重计数。
- 统计范围：案例主档；明确要求子表范围时按指定来源处理。
- 默认过滤：无。`t_caseinfo.c_mark` 作为技术标记，不解释为有效状态，不默认过滤为 `1`。
- 当前结果：39。此数为当前快照核查结果，不硬编码为未来答案。

该定义基于主键及粒度，按用户委托采用为本项目口径，不需要用户提供领域背景才能使用。

# 已分类案例数

<!-- planning -->
已分类案例默认指案例主档中具有分类记录的不同案例编码；有分类记录和已描述案例采用此范围。明确问分类表编码数时才包含未匹配主档的编码。
<!-- /planning -->

默认“已分类案例数”统计 `t_caseinfo.c_caseCode` 中存在 `t_casedesc.c_caseCode` 分类记录的不同编码，当前为 35；主档没有分类记录的案例为 4。

明确问“分类表案例编码数”时对 `t_casedesc.c_caseCode` 去重，当前 36，其中 1 个编码不在主档。两者不能混用。案例主档与分类记录的业务连接已列入本次审核启用的关系目录。

# 按岩爆等级统计案例数

<!-- planning -->
按岩爆等级统计案例数默认限定案例主档范围，按案例编码去重；完整分组保留无分类的案例。强烈及以上包含强烈和极强，范围按业务顺序解释。
<!-- /planning -->

- 默认范围：`t_caseinfo` 主档；分类字段为 `t_casedesc.c_rockLevel`。
- 已观测等级对应主档案例数：轻微 17、中等 12、强烈 5、极强 1，共 35；另有 4 个主档案例没有分类记录。
- 完整分组使用保留全部主档的连接方式，并报告无分类组；明确只看已分类时排除未分类主档。
- 案例编码为 NULL 不计；原始 NULL 和空字符串分别保留，不能改写成“轻微”。没有分类行与分类行存在但等级缺失需要区分时分别展示。
- 等级范围顺序：轻微 < 中等 < 强烈 < 极强。“强烈及以上”用 `强烈`、`极强` 的集合匹配，当前为 6。

仅当用户明确要求分类表范围时才采用 36 个分类编码，其中强烈 6；主档范围的强烈 5 与分类表范围的强烈 6 不混用。

# 按时空类型或机制统计案例数

<!-- planning -->
按时空类型或机制统计案例默认限定主档范围，按案例编码去重；完整分组保留缺失状态。时间序列分类用于明确的时间序列问题。
<!-- /planning -->

使用 `t_casedesc.c_spaceTime` 或 `t_casedesc.c_mechanism` 对主档范围的不同 `t_caseinfo.c_caseCode` 分组或过滤。完整分组保留没有分类记录的主档；精确类别过滤自然不匹配缺失。NULL 与空字符串分别保留。用户明确指定分类表原始范围或时间序列范围时使用对应来源并说明范围。

# 明细记录数量

<!-- planning -->
地质、爆坑、支护、监测和时间序列记录分别按自身粒度计数。监测默认数物理行，完整行去重需明确提出；多个一对多明细先分别聚合，避免计数放大。
<!-- /planning -->

| 问法 | 统计对象 |
|---|---|
| 地质结构记录数 | `t_geology.c_caseCode` 与 `t_geology.c_groupNo` 定义的记录 |
| 爆坑数量 | `t_rockdesc.c_caseCode` 与 `t_rockdesc.c_craterNo` 定义的记录 |
| 支护记录数 | 默认 `t_support.i_serialid`；明确新版则用 `t_supportnew.i_serialid` |
| 监测汇总记录数 | `t_activeinfo` 物理行，当前 37；完整行去重口径为 24 |
| 时间序列记录数 | `t_casetimeinfo.i_serialid` |

连接后的组合行数不是任意一个明细对象的数量；存在扇出时先聚合目标明细，再连接。

# 时间范围

<!-- planning -->
案例按日、月、年统计默认使用案例发生日期。该日期在当前快照中全部是完整规范日期，可以按日历年月分组；未要求时间范围时不附加过滤。爆破、岩爆起止和监测时间须按各自含义处理。
<!-- /planning -->

案例主时间绑定 `t_caseinfo.c_happenDate`。DDL 明确称“发生日期”；当前 39/39 行均为有效 `YYYY-MM-DD` 日期，因此可按日期、月份、年份统计。它是日历日期，不附加时区或虚构时分秒。日期过滤在已验证格式下可使用 ISO 日期边界；按年/月分组采用目标数据库支持的日期函数。

`t_caseinfo.c_blastDatetime`、`t_caseinfo.c_rockBeginTime`、`t_caseinfo.c_rockEndTime` 存在不完整或多种时间格式，不套用主日期规则；不自动补年计算时差。`t_casetimeinfo.c_happenDate` 属于时间序列记录自己的日期，用于明确的时间序列分析。

主日期解析失败或未来出现新格式时应报告格式异常，而非将非法日期隐式转换为零值。
